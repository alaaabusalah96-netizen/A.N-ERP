## STEP 3 — `scripts/ops/create_an_erp_app_role.sql`

```sql
-- AN-FIX-PG-ROLE-1
-- Run as a superuser on the TARGET database once.
-- Replace passwords out-of-band; do not commit secrets.

DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'an_erp_app') THEN
    CREATE ROLE an_erp_app LOGIN
      NOSUPERUSER
      NOCREATEDB
      NOCREATEROLE
      NOINHERIT
      NOBYPASSRLS
      CONNECTION LIMIT 50;
  ELSE
    ALTER ROLE an_erp_app WITH
      LOGIN
      NOSUPERUSER
      NOCREATEDB
      NOCREATEROLE
      NOBYPASSRLS;
  END IF;
END
$$;

-- Grant connect on current DB (run while connected to the app database):
-- GRANT CONNECT ON DATABASE current_database() TO an_erp_app;
GRANT USAGE ON SCHEMA public TO an_erp_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO an_erp_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO an_erp_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO an_erp_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO an_erp_app;

-- Force RLS awareness reminder (policies must already exist for tenant columns):
-- ALTER TABLE ... ENABLE ROW LEVEL SECURITY;

COMMENT ON ROLE an_erp_app IS 'AN-FIX-PG-ROLE-1: app role without BYPASSRLS for multi-tenant Shared isolation';
```

## STEP 3b — `docs/ops/PG-ROLE-NO-BYPASSRLS.md`

```markdown
# PostgreSQL app role without BYPASSRLS

## Why
If `DATABASE_URL` connects as a role with `rolbypassrls=true`, Row Level Security never applies and Shared multi-tenant isolation is ineffective.

## One-time setup
1. Connect as superuser to the application database.
2. Run `scripts/ops/create_an_erp_app_role.sql`.
3. Set a strong password for `an_erp_app` (psql `\password an_erp_app`).
4. Point application `DATABASE_URL` at:
   `postgresql://an_erp_app:***@host:5432/dbname`
5. Verify:
```sql
SELECT rolname, rolsuper, rolbypassrls
FROM pg_roles
WHERE rolname = current_user;
```
Expected: `rolsuper=false`, `rolbypassrls=false`.

## Optional probe
```bash
AN_PG_ROLE_PROBE=1 npx tsx scripts/ops/probePgRole.ts
```

## Studio / Google AI Studio
You cannot complete production DB grants from the app container alone. Run SQL on your managed Postgres (Neon/Supabase/Cloud SQL/etc.), then update the secret `DATABASE_URL`.
```

## STEP 3c — `scripts/ops/probePgRole.ts`

```typescript
/**
 * Read-only probe: reports current_user rolsuper/rolbypassrls when AN_PG_ROLE_PROBE=1.
 */
import pg from 'pg';

async function main() {
  if (process.env.AN_PG_ROLE_PROBE !== '1' && process.env.AN_PG_ROLE_PROBE !== 'true') {
    console.log('SKIP probe (set AN_PG_ROLE_PROBE=1 to run)');
    process.exit(0);
  }
  const url = process.env.DATABASE_URL;
  if (!url) {
    console.error('DATABASE_URL not set');
    process.exit(1);
  }
  const client = new pg.Client({ connectionString: url });
  await client.connect();
  const r = await client.query(
    `SELECT current_user AS user,
            rolsuper,
            rolbypassrls
     FROM pg_roles WHERE rolname = current_user`
  );
  console.log(JSON.stringify(r.rows[0] || {}, null, 2));
  const row = r.rows[0];
  if (row?.rolbypassrls === true) {
    console.error('FAIL: rolbypassrls=true — not safe for Shared RLS multi-tenant');
    await client.end();
    process.exit(2);
  }
  if (row?.rolsuper === true) {
    console.error('FAIL: rolsuper=true');
    await client.end();
    process.exit(2);
  }
  console.log('PASS: role is non-superuser and NOBYPASSRLS');
  await client.end();
}

main().catch((e) => {
  console.error(e?.message || e);
  process.exit(1);
});
```
If `pg` is not a dependency, use existing Postgres client import path from the project (e.g. from adapter) or mark probe optional and skip with message when module missing.
